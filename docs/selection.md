# 需求价值评分

当前目标：帮刚上手、面向英语用户的独立开发者，从垂直社区发现值得继续验证的小工具需求。评分替代原来的 AI 新闻注意力与信源精选门槛。

首页、搜索和 RSS 按需求价值分降序排列，同分按时间、ID 降序，未评分排在最后。所有内容平级保留，没有分类、精选或低分隐藏。

## 五维依据

每维 0–10，缺少证据记为 `null`，计算时贡献 0。未提供证据不等于确认不存在需求。

| 维度 | 看什么 | 不推断什么 |
|---|---|---|
| 具体场景 | 谁、在哪一步、输入与预期输出、实际障碍 | 不用品牌、官方身份、点赞量补分 |
| 重复成本 | 频率、耗时、返工、错误、明确损失 | 不因情绪强烈而推断很严重 |
| 方案缺口 | 已尝试的工具、变通办法、仍卡住的一步 | 不断言全市场没有竞品 |
| 付费证据 | 当前相关支出、委托、预算、实际雇用 | 不把愿意省时间等同愿意买新 SaaS |
| 小切口明确度 | 可拿样本验证的整理、转换、核对、提醒、交接 | 不保证技术可行或开发天数，不将整套 ERP 当作小工具 |

`industry/selection.ts` 的 `DEMAND_SCORING` 保存权重，`industry/prompts/selection-score.md` 定义取证规则。内部内容类型用于选权重，不会生成前台分类或标签。各行权重之和为 10，后端做整数加权，模型不能直接报总分。

例如流程痛点权重为 **3、3、2、1、1**。五维均为 8 时是 80 分；付费证据缺失则为 72 分，并明确标为“未提供”，不会捏造预算补齐。

## 噪声与缺失材料

- 只有营销、已明确完整解决且无剩余缺口、与业务工具需求无关的资料：需求价值为 0，仍展示。有人推荐一个工具不代表问题已解决；未采集的回复不作证据。
- 只有标题：保留标题/摘要，分数为空。可读取正文的帖子先进入正文提取；提取失败也不编分数。
- 每个正向维度都需要原文连续片段。后端核对片段是否确实存在于本次输入；不匹配的维度不计分。
- 评分带版本和输入修订号。旧新闻分数、旧提示词分数和修改前的资料评分不能作为当前需求价值分。

## 执行与成本

DeepSeek Flash 每条一次请求，同时生成中文标题、摘要和五维评估。后端计算分数与说明，保存各维原文证据供后台查看。相同材料与提示词复用回执；所有调用受请求预算和超时约束。

没配置 Key 或关闭模型时仍能阅读原始资料，显示“暂无评分”。更新后，没有当前评分版本的历史摘要会由后台任务分批重处理，不在页面请求中调用模型。公开 API v1 的 `by=timeline/published` 保留原接口的时间排序语义，同时返回需求分及依据。

## 校准状态

这些权重是根据用户目标制定的初始研究排序规则，**尚未用用户标注的真实样本验证排序质量**，不代表市场成功概率。没有沿用 T1/T2 新闻入选门槛，也未新设筛选门槛。后续校准应比较同一批真实帖子哪些更值得访谈，重点检查付费证据、已解决状态和小工具边界；不能把模型自己的分数当作人工金标。
